# Naming Conventions

This document defines the naming conventions for the SchoolGantt project to ensure consistency and maintainability.

## File and Directory Naming

### Vue Components
- **Format**: PascalCase
- **Extension**: `.vue`
- **Examples**: 
  - `GanttChart.vue`
  - `TaskForm.vue`
  - `TaskCard.vue`
  - `DataManager.vue`

### JavaScript Files
- **Format**: camelCase for utilities, kebab-case for modules
- **Extension**: `.js`
- **Examples**:
  - `index.js` (barrel exports)
  - `main.js` (entry point)
  - `task-utils.js` (utility modules)

### Vue Views/Pages
- **Format**: PascalCase with "View" suffix
- **Extension**: `.vue`
- **Examples**:
  - `GanttView.vue`
  - `SettingsView.vue`
  - `DashboardView.vue`

### Directories
- **Format**: kebab-case (lowercase with hyphens)
- **Examples**:
  - `components/`
  - `charts/`
  - `forms/`
  - `ui/`
  - `management/`
  - `assets/`
  - `styles/`

### CSS/Style Files
- **Format**: kebab-case
- **Extension**: `.css`, `.scss`
- **Examples**:
  - `global.css`
  - `component-styles.css`
  - `theme-variables.scss`

### Asset Files
- **Format**: kebab-case
- **Examples**:
  - `app-logo.png`
  - `task-icon.svg`
  - `background-pattern.jpg`

## Code Naming Conventions

### Vue Component Properties

#### Props
- **Format**: camelCase
- **Examples**:
  ```javascript
  props: {
    selectedTaskId: String,
    allTasks: Array,
    isEditing: Boolean,
    maxWidth: Number
  }
  ```

#### Data Properties
- **Format**: camelCase
- **Examples**:
  ```javascript
  data() {
    return {
      currentView: 'timeline',
      showTaskModal: false,
      editingTask: null,
      selectedItems: []
    }
  }
  ```

#### Computed Properties
- **Format**: camelCase, descriptive names
- **Examples**:
  ```javascript
  computed: {
    sortedTasks() { ... },
    completedTaskCount() { ... },
    isFormValid() { ... },
    filteredResults() { ... }
  }
  ```

#### Methods
- **Format**: camelCase, verb-based names
- **Examples**:
  ```javascript
  methods: {
    handleTaskSubmit() { ... },
    selectTask() { ... },
    validateForm() { ... },
    exportData() { ... }
  }
  ```

#### Events
- **Format**: kebab-case
- **Examples**:
  ```javascript
  this.$emit('task-select', taskId)
  this.$emit('form-submit', formData)
  this.$emit('data-updated', newData)
  ```

### JavaScript Variables and Functions

#### Variables
- **Format**: camelCase
- **Examples**:
  ```javascript
  const taskList = []
  let currentUser = null
  const isDataLoaded = false
  ```

#### Constants
- **Format**: SCREAMING_SNAKE_CASE
- **Examples**:
  ```javascript
  const MAX_TASKS = 100
  const DEFAULT_PRIORITY = 'medium'
  const API_ENDPOINTS = { ... }
  ```

#### Functions
- **Format**: camelCase, verb-based names
- **Examples**:
  ```javascript
  function generateId() { ... }
  function validateTask() { ... }
  function formatDate() { ... }
  ```

### CSS Classes and IDs

#### CSS Classes
- **Format**: kebab-case with BEM methodology
- **Examples**:
  ```css
  .task-card { ... }
  .task-card__title { ... }
  .task-card__title--highlighted { ... }
  .gantt-chart { ... }
  .gantt-chart__timeline { ... }
  ```

#### CSS IDs
- **Format**: kebab-case (use sparingly)
- **Examples**:
  ```css
  #app { ... }
  #main-content { ... }
  ```

#### CSS Custom Properties (Variables)
- **Format**: kebab-case with descriptive prefixes
- **Examples**:
  ```css
  :root {
    --color-primary: #007bff;
    --color-secondary: #6c757d;
    --spacing-small: 0.5rem;
    --spacing-medium: 1rem;
    --font-size-large: 1.25rem;
  }
  ```

## Vuex Store Naming

### State Properties
- **Format**: camelCase
- **Examples**:
  ```javascript
  state: {
    tasks: [],
    currentProject: {},
    isLoading: false,
    lastSaved: null
  }
  ```

### Mutations
- **Format**: SCREAMING_SNAKE_CASE
- **Examples**:
  ```javascript
  mutations: {
    SET_TASKS(state, tasks) { ... },
    ADD_TASK(state, task) { ... },
    UPDATE_TASK(state, { id, updates }) { ... },
    DELETE_TASK(state, taskId) { ... }
  }
  ```

### Actions
- **Format**: camelCase
- **Examples**:
  ```javascript
  actions: {
    loadTasks({ commit }) { ... },
    saveTask({ commit }, task) { ... },
    deleteTask({ commit }, taskId) { ... },
    exportProject({ state }) { ... }
  }
  ```

### Getters
- **Format**: camelCase, descriptive names
- **Examples**:
  ```javascript
  getters: {
    allTasks: state => state.tasks,
    completedTasks: state => state.tasks.filter(t => t.status === 'completed'),
    taskById: state => id => state.tasks.find(t => t.id === id)
  }
  ```

## Import/Export Naming

### Named Exports
- **Format**: PascalCase for components, camelCase for utilities
- **Examples**:
  ```javascript
  // Components
  export { GanttChart } from './charts'
  export { TaskForm } from './forms'
  
  // Utilities
  export { generateId, validateTask } from './utils'
  ```

### Default Exports
- **Format**: Match the file name
- **Examples**:
  ```javascript
  // In TaskCard.vue
  export default {
    name: 'TaskCard',
    // ...
  }
  ```

### Import Aliases
- **Format**: camelCase, descriptive
- **Examples**:
  ```javascript
  import { GanttChart as TimelineChart } from '@/components/charts'
  import { validateTask as isValidTask } from '@/utils/validation'
  ```

## Documentation Naming

### README Files
- **Format**: UPPERCASE
- **Examples**: `README.md`

### Documentation Files
- **Format**: kebab-case
- **Examples**:
  - `naming-conventions.md`
  - `development-guide.md`
  - `api-documentation.md`

## Git Naming

### Branch Names
- **Format**: kebab-case with type prefix
- **Examples**:
  - `feature/task-dependencies`
  - `bugfix/gantt-chart-rendering`
  - `docs/component-documentation`

### Commit Messages
- **Format**: Conventional Commits
- **Examples**:
  - `feat(components): add task dependency management`
  - `fix(gantt): resolve drag-and-drop positioning issue`
  - `docs(readme): update project structure documentation`

## Validation Rules

These naming conventions should be enforced through:

1. **ESLint Rules**: Configure ESLint to check naming patterns
2. **Code Reviews**: Manual verification during pull requests
3. **Documentation**: Regular updates to this document
4. **IDE Configuration**: Set up IDE to suggest correct naming patterns

## Exceptions

Exceptions to these rules should be:
1. **Documented**: Clearly explained in code comments
2. **Justified**: Have a technical or business reason
3. **Consistent**: Applied uniformly across similar cases
4. **Reviewed**: Approved through code review process

Consider using these tools to enforce naming conventions:

- **VS Code Extensions**: Real-time naming suggestions
